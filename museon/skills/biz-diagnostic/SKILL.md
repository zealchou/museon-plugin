# 生意診斷與規劃

用 MuseON 的方法，讓你的 AI 陪你找出生意卡在哪裡，整理市場機會、合作風險與下一步方案。

## 用途分流（優先）

真實會議內容轉交「會議記錄與追蹤」（`skills/meeting-notes/SKILL.md`）；企業／個人／合作／投資背景查證轉交「盡職調查」（`skills/dd/SKILL.md`）；提案條件與報價規劃轉交「提案與報價」（`skills/proposal-quote/SKILL.md`）。依主要目的選用途；跨用途時沿用已有資訊與成果。 商業診斷、市場研究、品牌與價值仍留此入口；`biz-chain` 走到提案／報價時交接相應用途。

## AI 路由

> 在總入口分派後，用於商業模式診斷、創業評估、市場調研，以及品牌與價值規劃。診斷先和會員確認目前是構想、試點或營運階段，再辨識創投或顧問視角，依階段使用相應評估方式；查證以可回查資料為依據，無資料就標待查。以「要判斷生意是否合理」為主；內容與決策已確定、只要寫好文字時交文字入口。需要商業顧問全程規劃時可走串接路線，也可依需求單獨進入；品牌定案、對外價格與資源承諾由有權限的人確認。

## method 對照

| method | 用途與分支 |
|---|---|
| `business-diagnosis` | 融合後的商業診斷；創投（`vc`）／顧問兩視角，先確認構想、試點或營運階段；顧問視角不出總分。 |
| `market-research` | 市場機會、競爭、客群與定位研究；調查結果可作後續規劃依據。 |
| `dd` | 轉交盡職調查入口處理背景與風險調查；企業／個人／合作／投資四條路線，依對象與決策目的選擇。 |
| `brand` | 品牌探索與建構；釐清客群、定位及品牌表達。 |
| `value-evidence` | 價值與投資效益的證據整理；說清楚效益憑什麼成立。 |
| `proposal` | 轉交提案與報價入口形成有依據的提案；包含尚待釐清的方案、需求與條件。 |
| `quote` | 轉交提案與報價入口作報價規劃；價格與成本、預算不相容時，調整範圍、補證據或停止，不自行改數字湊合。 |
| `biz-chain` | 商業顧問串接：商業診斷（顧問視角）→品牌→價值→提案→報價；各段也可單獨進入。 |

`startup-kickoff` 只作 `business-diagnosis` 創投視角的既有相容別名，不列為另一個獨立方法；`business-12` 已由融合後方法取代，不再列為現行獨立選項。創投與顧問是同一 method 的兩種視角，本文不自行新增視角參數名稱或代碼。商業調查內需要查證或獨立挑戰時，沿原方法銜接相關能力，會員主入口仍是本節。
